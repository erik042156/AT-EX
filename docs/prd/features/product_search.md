# 상품 검색 (Product Search) 기능 상세 PRD

**작성 일자**: 2026-07-22
**최종 수정일**: 2026-07-23 (v1.6 - 홈 페이지 직접 검색 가능 여부를 확정 사실("검색은 `/products` 페이지에서만 가능하며 홈 페이지에는 검색 기능이 없음")로 전환, 상품 상세 페이지 URL 패턴 및 View Product 버튼의 이동 대상 참고 반영)
**버전**: 1.6
**상태**: URL 구조, 검색결과없음 케이스, 로그인 여부 무관 접근, 유효/무효 검색 키워드, 페이지네이션 없음(단일 페이지+스크롤), 결과 카운트 텍스트 없음, 로딩 표시 없음, View Product 상시노출, 검색 매칭 방식(대소문자 무시+완전일치), 상품 카드 표시 정보(이미지/가격/상품명/Add to cart/View Product 5개, 추가 항목 없음), 검색 대상 범위(상품명 한정, 설명/카테고리 미포함), 전체 상품 개수(34개), 홈 페이지 직접 검색 불가(검색은 `/products` 페이지에서만 가능)가 모두 확인 완료. 상품 상세 페이지 URL 패턴(`/product_details/{id}`, id 1~8)과 상품 카드 "View Product" 클릭 시 해당 URL로 이동한다는 사실도 참고로 반영됨(이 문서의 핵심 범위는 검색이므로 상세 페이지 자체는 깊이 다루지 않음). 남은 것은 각 UI 요소의 실제 Locator 공유(Page Object 구현 착수 시 진행)뿐임

## 1. 기능명

- **한국어명**: 상품 검색 (전체 제품 목록 조회 포함)
- **영문명**: Product Search
- **기능 ID**: PRODUCT_SEARCH

---

## 2. 기능 목적

사용자가 키워드를 입력하여 원하는 상품을 검색하거나, 검색어 없이 "Products" 메뉴로 진입하여 사이트에서 판매 중인 전체 상품 목록을 조회할 수 있도록 하는 기능입니다.

### 비즈니스 가치
- 사용자가 원하는 상품을 빠르게 찾을 수 있도록 지원
- 검색 결과 및 상품 목록의 정확성 확보를 통한 사용자 신뢰 확보
- 장바구니 추가, 주문 등 이후 구매 전환 흐름의 시작점 역할 (project-prd.md 9.1 단계4 "장바구니에 상품 추가"로 연결)

## 3. 프로젝트 전체 PRD와의 연관성

### 기준 문서
**참고**: `docs/prd/project-prd.md`

### 연관 섹션
- **5.2 MVP 대상 기능**: 우선순위 2(높음) - "제품 검색(키워드 기반 검색)"과 "제품 목록 조회"가 별도 항목으로 명시됨 (134-136행)
- **7.1 MVP 스코프**: "4. 상품 검색(Product Search) - 키워드 기반 상품 검색, 검색 결과 조회" (188-190행)
- **8.1 Phase 1**: "4. 상품 검색(Product Search): 검색 페이지 접근 → 검색 키워드 입력 → 검색 결과 조회 → 검색 결과 아이템 확인" 및 산출물로 `docs/prd/features/product_search.md`가 명시됨 (226-236행)
- **9.1 주요 사용자 흐름 단계 3**: "홈 페이지 또는 'Products' 페이지로 이동 → 검색창에 상품 키워드 입력 → 'Search' 버튼 클릭 또는 엔터 키 입력 → 검색 결과 페이지 표시 → 검색 결과에 해당 상품들이 나열됨" (311-318행)

### 이번 문서의 범위 결정
project-prd.md 5.2 우선순위 표에는 "제품 검색"과 "제품 목록 조회"가 별도 항목으로 나열되어 있으나(134-136행), 9.1 사용자 흐름에는 "제품 목록 조회"가 독립된 흐름으로 서술되어 있지 않고 검색 결과 조회 흐름에 통합되어 있습니다. 이에 따라 이번 PRD는 **"키워드 기반 상품 검색"을 중심**으로 작성하되, **검색어 없이 "Products" 메뉴로 진입해 전체 상품 목록을 조회하는 흐름("전체 제품 목록 조회")도 관련 기능으로 함께 다룹니다.** 두 흐름은 동일한 URL(`https://automationexercise.com/products`)에서 쿼리 파라미터(`?search=키워드`) 유무로만 구분되는 **동일 화면**임이 실사이트 스크린샷으로 **확정**되었습니다. 검색어의 유무만 다른 특수 케이스로 취급합니다.

### 의존성
- **선행 기능 없음 (확정)**: 로그인 (Login) - 상품 검색 및 상품 목록 조회는 로그인 여부와 무관하게 이용 가능함이 확인되었습니다 (섹션 6, 18 참고)
- **후행 기능**: 장바구니 (Shopping Cart) - 검색 결과 또는 목록에서 상품을 선택해 장바구니에 추가하는 흐름으로 이어짐 (project-prd.md 9.1 단계 4 참고)

## 4. 대상 URL 또는 진입 경로

**확정**: 이번 섹션의 URL은 실사이트 스크린샷으로 확인되었습니다.

### 확정된 URL
- **상품 목록 페이지 URL (확정)**: `https://automationexercise.com/products`
- **검색 결과 URL (확정)**: `https://automationexercise.com/products?search=키워드` (예: `https://automationexercise.com/products?search=d`) — 상품 목록 페이지와 동일 URL에 쿼리 파라미터 `search`가 추가되는 형태

### 진입 경로
1. **홈 페이지에서 진입 (전체 목록 조회)**: 홈 페이지 상단 네비게이션의 "Products" 링크 클릭 → 검색어 없이 전체 상품 목록이 표시되는 `https://automationexercise.com/products` 페이지로 이동
2. **상품 목록 페이지에서 검색 수행**: 상품 목록 페이지 내 검색창에 키워드 입력 후 Search 버튼(또는 엔터 키) 클릭 → 동일 페이지 레이아웃에서 `?search=키워드` 쿼리 파라미터가 붙은 URL로 검색 결과 표시
3. **홈 페이지에서 직접 검색 불가 (확정, v1.6)**: 상품 검색은 상품 목록 페이지(`https://automationexercise.com/products`)에서만 가능하며, 홈 페이지에는 검색 기능(검색창)이 노출되지 않는다는 것이 실제 사이트 확인으로 확정되었습니다. project-prd.md 9.1(312행)의 "홈 페이지 또는 'Products' 페이지로 이동"이라는 서술은 이 확정 사실과 다르나, project-prd.md 자체의 수정은 이번 개정 범위에 포함하지 않습니다 (참고로만 기록).

### 참고: 상품 상세 페이지 URL
- 상품 카드의 "View Product" 버튼 클릭 시 상품 상세 페이지(`https://automationexercise.com/product_details/{id}`, `id`는 1~8 범위의 정수)로 이동합니다 (확정, v1.6). 이 문서의 핵심 범위는 검색이므로 상세 페이지 자체의 상세 동작은 다루지 않으며, `shopping_cart.md`에서 상세화됩니다.

## 5. 사용자 역할

### 대상 사용자 (확정)
- **게스트 (비회원)**: 로그인하지 않은 상태에서도 상품 검색 및 목록 조회가 가능함 (확정)
- **기존 회원 (Registered User)**: 로그인 상태에서도 동일하게 상품 검색 및 목록 조회 가능

### 사용자 시나리오
- 신규/비회원 방문자가 특정 상품을 찾기 위해 키워드로 검색
- 방문자가 특정 상품 없이 전체 상품군을 둘러보기 위해 "Products" 메뉴로 진입
- 로그인한 회원이 검색 후 상품을 장바구니에 담기 위한 사전 단계로 검색 수행

## 6. 사전 조건 (Precondition)

### 필수 조건 (확정)
1. **로그인 불필요 (확정)**: 상품 검색 및 상품 목록 조회는 로그인 여부와 무관하게 이용 가능함이 확인되었습니다.
2. **브라우저 상태**: 테스트 시작 전 상태 - 로그인 상태이든 비로그인 상태이든 무관하게 테스트 가능 (확정)
3. **사이트 접근**: Automation Exercise 사이트에 접근 가능 (인터넷 연결 정상, 사이트 운영 중)

### 테스트 데이터 준비
- 검색 시 사용할 유효한 키워드 (실제 매칭 확인된 키워드: `Blue`, `Top`, `Tshirt`, `Dress`, `Kids` - 섹션 17 참고)
- 검색 결과가 없을 것으로 확인된 키워드 (`mondaykiz`, `testkeyword`, `qwer`, `asdf` - 섹션 17 참고)

## 8. 정상 사용자 흐름 (Happy Path)

**주의**: 아래 흐름은 project-prd.md 9.1(311-318행)의 서술을 기반으로 한 **가정된 흐름**이며, 실사이트 방문으로 단계별 세부사항이 확인되지 않았습니다.

### 흐름 1: 키워드로 검색하여 결과 확인

**시작 조건**: 상품 목록 페이지(또는 홈 페이지) 방문, 로그인 여부 무관

**단계별 행동**:
1. 사용자가 홈 페이지 또는 "Products" 페이지로 이동
2. 검색창에 상품 키워드 입력 (예: `Blue`, `Top`, `Tshirt`, `Dress`, `Kids` - 실제 매칭 확인됨, 섹션 17 참고)
3. Search 버튼 클릭 또는 엔터 키 입력
4. 시스템이 입력한 키워드와 일치하는 상품을 조회
5. URL이 `https://automationexercise.com/products?search=키워드` 형태로 변경되며, 동일 페이지 레이아웃에서 검색 결과가 표시됨(확정)
6. 페이지 제목이 "SEARCHED PRODUCTS"로 표시되고(확정), 입력한 키워드와 관련된 상품들이 목록 형태로 나열됨

**기대 결과**:
- URL이 `?search=키워드` 쿼리 파라미터를 포함한 형태로 변경됨
- 페이지 제목이 "SEARCHED PRODUCTS"로 표시됨
- 입력한 키워드와 관련된 상품들이 검색 결과에 표시됨 (project-prd.md 9.1, 318행)
- 각 상품 카드에 이미지, 가격, 상품명, "Add to cart" 버튼, "View Product" 링크 5개 항목이 표시됨(확정, 추가 항목 없음)

**소요 시간**: 추정 1~3초 (네트워크 지연 포함, 확인 필요)

---

### 흐름 2: 검색어 없이 전체 상품 목록 조회

**시작 조건**: 홈 페이지 방문, 로그인 여부 무관

**단계별 행동**:
1. 사용자가 홈 페이지 상단 네비게이션의 "Products" 링크 클릭
2. 검색어를 입력하지 않은 상태로 `https://automationexercise.com/products` 페이지에 진입
3. 페이지 제목 "ALL PRODUCTS"와 함께 사이트에 등록된 전체 상품이 목록(그리드) 형태로 표시됨
4. 페이지네이션 없이 단일 페이지에 전체 상품이 표시되며, 사용자는 페이지 하단으로 스크롤하여 모든 상품을 확인할 수 있음 (확정)

**기대 결과**:
- URL이 `https://automationexercise.com/products`로 이동함
- 검색 조건 없이 전체 상품이 목록에 표시됨
- 상품 목록이 비어있지 않으며, 사이트에 등록된 전체 상품 개수는 34개임(확정)
- 페이지네이션 없이 단일 페이지에 전체 상품이 표시되며, 스크롤을 통해 전체 상품을 확인할 수 있음 (확정)

**소요 시간**: 추정 1~3초 (확인 필요)

## 9. 예외 사용자 흐름 (Exception Flow)

### 흐름 1: 존재하지 않는 키워드로 검색

**설명**: 사이트에 등록된 어떤 상품명과도 일치하지 않는 것으로 확인된 키워드로 검색을 시도하는 흐름입니다.

**단계별 행동**:
1. 검색창에 결과가 없는 것으로 확인된 키워드 입력 (예: `mondaykiz`, 그 외 `testkeyword`, `qwer`, `asdf`도 동일하게 결과 없음이 확인됨, 섹션 17 참고)
2. Search 버튼 클릭
3. 시스템이 일치하는 상품을 찾지 못함
4. 페이지 제목 "SEARCHED PRODUCTS"만 남고, 그 아래 상품 카드 없이 완전히 빈 화면이 표시됨(확정). 별도의 "No products found" 류 안내 문구는 없음(확정)

**기대 결과**: 페이지 제목 "SEARCHED PRODUCTS"는 표시되나 상품 카드가 0개인 빈 화면이 표시되며, 별도 안내 문구는 노출되지 않음

### 흐름 2: 검색어를 입력하지 않고 Search 버튼 클릭 (자동화 범위 제외, 확정)

**설명**: 검색창을 비운 상태로 Search 버튼을 클릭하는 흐름입니다. 이 경우의 실제 동작(전체 상품 목록 표시 여부, 별도의 유효성 검사 메시지 표시 여부)은 확인되지 않았으나, 이 흐름 자체는 **자동화 범위에서 제외하기로 확정**되었습니다 (섹션 12 참고).

## 10. 기능 요구사항

### 요구사항 정의

**SEARCH-REQ-001**: 키워드 입력
- 사용자는 검색 입력란에 텍스트 키워드를 입력할 수 있어야 한다.

**SEARCH-REQ-002**: 키워드 기반 검색 수행
- 사용자가 유효한 키워드를 입력한 후 "Search" 버튼을 클릭하거나 엔터 키를 입력하면, 시스템은 해당 키워드와 관련된 상품을 조회해야 한다.
- 조회된 상품은 화면에 목록(그리드) 형태로 표시되어야 한다.

**SEARCH-REQ-003**: 검색 결과 상품 정보 표시
- 검색 결과에 나열되는 각 상품에는 상품 이미지, 가격, 상품명, "Add to cart" 버튼, "View Product" 링크 5개 항목이 표시되어야 하며, 그 외 추가 표시 항목은 없다. (확정)

**SEARCH-REQ-004**: 검색 결과 없음 처리
- 입력한 키워드와 일치하는 상품이 없는 경우, 시스템은 오류 없이 페이지 제목("SEARCHED PRODUCTS")만 표시하고 그 아래 상품 카드 없이 빈 화면을 표시해야 한다. 별도의 안내 문구는 표시하지 않는다. (확정)

**SEARCH-REQ-005**: 검색어 없이 전체 상품 목록 조회
- 사용자가 검색어를 입력하지 않고 "Products" 메뉴를 통해 상품 목록 페이지에 진입하면, 시스템은 사이트에 등록된 전체 상품 목록을 표시해야 한다.

**SEARCH-REQ-006**: 로그인 여부와 무관한 접근성 (확정)
- 상품 검색 및 상품 목록 조회 기능은 로그인 여부와 무관하게 이용 가능해야 한다. (확정)

**SEARCH-REQ-008**: 검색 매칭 방식 (확정)
- 검색은 대소문자를 구분하지 않아야 한다.
- 키워드가 상품명(또는 상품명 내 단어)과 완전히 일치하는 경우에만 결과에 노출되어야 한다 (부분 문자열 일치가 아님).

**SEARCH-REQ-009**: 페이지네이션 없음 (확정)
- 상품 목록/검색 결과는 페이지네이션 없이 단일 페이지에 모두 표시되어야 하며, 사용자는 스크롤을 통해 전체 상품을 확인할 수 있어야 한다.

**SEARCH-REQ-010**: 검색 대상 필드 (확정)
- 검색은 상품명(product name)만을 대상으로 매칭해야 하며, 상품 설명(description)이나 카테고리는 검색 대상에 포함되지 않아야 한다.

### NOR-003: 대소문자 구분 없이 검색

**시나리오명**: 대문자/소문자를 다르게 입력해도 동일한 검색 결과가 노출되는지 확인

**전제조건**:
- 상품 목록 페이지(또는 검색이 가능한 페이지)가 표시됨
- 검색은 대소문자를 구분하지 않음이 확정됨 (섹션 10 SEARCH-REQ-008 참고)

**테스트 단계**:
1. 상품 목록 페이지(`https://automationexercise.com/products`) 진입
2. 검색 입력란에 대문자로 변형한 키워드 입력 (예: `TOP`)
3. Search 버튼 클릭 (또는 엔터 키 입력)
4. URL이 `https://automationexercise.com/products?search=TOP` 형태로 변경되고 검색 결과 표시 대기
5. 별도로 소문자 키워드 `Top`으로도 동일하게 검색을 수행하여 두 결과를 비교

**기대 결과**:
- URL에 `?search=TOP` 쿼리 파라미터가 포함됨
- `TOP`으로 검색한 결과와 `Top`으로 검색한 결과가 동일한 상품 목록(동일 개수, 동일 상품명)을 반환함
- 페이지 제목이 "SEARCHED PRODUCTS"로 표시됨

**검증 포인트**:
- ✅ URL에 `?search=` 쿼리 파라미터가 포함되는가?
- ✅ `TOP` 검색 결과의 상품 개수와 `Top` 검색 결과의 상품 개수가 동일한가?

## 14. 비정상 시나리오 (Abnormal Scenarios)

### ABN-001: 존재하지 않는 키워드로 검색

**시나리오명**: 사이트에 등록된 어떤 상품과도 일치하지 않는 키워드로 검색

**검증 포인트**:

- ✅ 페이지가 정상적으로 로드되며 서버 오류가 발생하지 않는가?

### Locator 선택 원칙

**우선순위** (CLAUDE.md 기준):
1. **id 속성** (가장 안정적)
   ```python
   SEARCH_INPUT = (By.ID, "search_product")
   ```
2. **data-* 속성** (테스트용)
   ```python
   SEARCH_BUTTON = (By.CSS_SELECTOR, "button[data-qa='search-button']")
   ```
3. **name 속성**
   ```python
   SEARCH_INPUT = (By.NAME, "search")
   ```
4. **안정적인 CSS Selector**
   ```python
   PRODUCT_CARDS = (By.CSS_SELECTOR, "div.features_items div.product-image-wrapper")
   ```
5. **상대 XPath** (마지막 수단)
   ```python
   PAGE_TITLE = (By.XPATH, "//div[@class='features_items']//h2[contains(text(),'PRODUCTS')]")
   ```

**금지**: Full XPath 절대 금지
```python
# ❌ 금지
SEARCH_INPUT = (By.XPATH, "/html/body/div[2]/div/div[1]/div/input")
```

**안내**: 위 Locator는 모두 예시 값입니다. 실제 id/name/data-* 속성은 Page Object 구현 착수 시 사용자가 실시간으로 공유할 예정이며, 별도의 사전 개발자 도구 조사는 필요하지 않습니다.

### Wait 처리 전략

**명시적 Wait 사용** (time.sleep() 절대 금지):

```python
# ✅ 올바른 방식 (예시 - 실제 코드 아님)
def search(self, keyword: str):
    wait.until(EC.element_to_be_clickable(self.SEARCH_INPUT))
    self.find_element(self.SEARCH_INPUT).send_keys(keyword)

    wait.until(EC.element_to_be_clickable(self.SEARCH_BUTTON))
    self.click(self.SEARCH_BUTTON)

    # 검색 결과 페이지 제목("SEARCHED PRODUCTS")이 나타날 때까지 대기
    # (결과 없음 시 별도 메시지 요소는 없으므로 상품 카드가 아닌 제목 요소 기준으로 대기)
    wait.until(
        EC.presence_of_element_located(self.PAGE_TITLE)
    )
```

### 동적 요소 처리

- **검색 결과 로드**: Search 버튼 클릭 후 페이지 제목("ALL PRODUCTS"/"SEARCHED PRODUCTS") 또는 상품 카드 목록이 나타날 때까지 명시적 대기 필요 (결과 없음 시에도 제목은 표시되므로 이를 기준으로 대기 가능)
- **로딩 표시**: 로딩 스피너는 존재하지 않음 (확정). 별도의 스피너 대기 로직 없이, 상품 카드 또는 페이지 제목 요소의 존재 여부로 대기 전략을 구성한다.
- **페이지네이션**: 페이지네이션은 존재하지 않으며(확정), 상품 목록/검색 결과는 단일 페이지에 모두 표시되고 스크롤로 전체 상품을 확인한다. 따라서 "다음 페이지" 대기/클릭 로직은 불필요하다. 전체 상품 개수 확인이 필요한 경우, 페이지 하단까지 스크롤(예: `driver.execute_script`를 통한 스크롤 또는 전체 요소 조회)하여 모든 상품 카드가 DOM에 존재하는지 확인하는 방식을 고려한다.
- **Add to cart / View Product 노출**: "Add to cart" 버튼과 "View Product" 링크는 hover 없이 기본 상태에서도 이미 DOM상 노출되어 있다(확정). 상품 카드에 마우스를 올렸을 때 나타나는 주황색 오버레이는 순수 시각 효과이므로, 자동화 시 별도의 hover 액션 없이 바로 클릭 가능할 것으로 추정된다. 다만 실제 클릭 가능 여부는 Page Object 구현 시 재확인이 필요하다.

### 기능/UI 관련 - 확인 완료 (v1.6)
